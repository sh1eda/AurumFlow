# Model Integration

## Purpose

This file defines how machine-learning artifacts may be integrated without silently treating the existing unverified model as production-ready.

The system must support rule-only operation while model artifacts are absent.

## Operating Modes

- `RULE_ONLY`: ML is not required. Signals are generated by SMC/ICT rules only.
- `HYBRID_RESEARCH`: ML predictions are logged and compared if artifacts and adapters are available. ML must not block, create, or modify trades.
- `HYBRID_VALIDATED`: ML may act as a filter, ranker, or confidence modifier only after approval.

## Adapter Contract

The strategy layer consumes only `ModelPrediction`:

- `direction`: `UP_HORIZON`, `NOT_UP_HORIZON`, or `UNAVAILABLE`.
- `confidence`: numeric value from `0.0` to `1.0`.
- `raw_prediction`: original model output or `null`.
- `probabilities`: class probability map.
- `model_version`: manifest-defined version string.
- `feature_timestamp`: timestamp of the feature row.
- `feature_hash`: deterministic hash of ordered input features.

No strategy or backtest module may load a pickle/joblib file directly.

## Required Manifest Fields

Each model artifact needs a manifest with:

- model path,
- model version,
- feature names and exact order,
- target horizon,
- class semantics,
- probability calibration status,
- preprocessing requirements,
- training data window,
- data hash or dataset identifier,
- validation report path.

Missing or incomplete manifests are non-blocking in `RULE_ONLY` and `HYBRID_RESEARCH`, but they prevent `HYBRID_VALIDATED`.

## Validation Statuses

- `NOT_EVALUATED`
- `INSUFFICIENT_EVIDENCE`
- `REJECTED`
- `APPROVED`

## HYBRID_VALIDATED Gate

Predeclared primary metric:
- after-cost out-of-sample expectancy.

Secondary metrics:
- max drawdown,
- profit factor,
- average R,
- fold-to-fold stability.

Approval requirements:
- physical artifact exists and loads through the adapter,
- manifest is complete,
- adapter verifies object type, feature order, class order, `predict_proba()` availability, missing-value behavior, and feature hash stability,
- feature generation is causal and uses closed candles only,
- chronological walk-forward validation is complete,
- validation uses spread, slippage, and commission,
- aggregate after-cost OOS expectancy is positive,
- aggregate after-cost OOS expectancy is better than the paired `RULE_ONLY` baseline,
- at least 5 chronological OOS folds are evaluated,
- at least 100 closed OOS trades are evaluated for the ML behavior.

If the minimum evidence thresholds are not met, status is `INSUFFICIENT_EVIDENCE`.

Do not approve ML based only on secondary metrics when primary expectancy worsens.
